Handover · Hiring Intelligence

Running Hiring Intelligence

Setting it up, demonstrating it, and working with it every day. Written for someone who has never opened the code and does not intend to — everything here is copy-paste.

Operator Saum Runs on one Windows machine Longer version RUNBOOK.md Handed over 2 September 2026

  1. The tool reads LinkedIn profiles through your own signed-in browser window. Not a fake account, not a stored password — a real Edge window you open and sign into yourself. So that window has to be open on the machine running the tool, and your account is the one that carries the risk. It is capped at 30 profiles per 12 hours and paced at about 25 seconds each for exactly that reason.

  2. It finds fewer people than a LinkedIn search, on purpose. Twenty people worth contacting beats five thousand rows. If a search returns twelve people, that is not a fault.

Part 1

The demo, end to end

About twelve minutes. The one thing that can go wrong live is timing: reading profiles takes ~25 seconds each, so a role started from scratch will not have a ranked list to show for several minutes. So you show two roles — one you prepared, one you run live.

Before they arrive

  1. Start everything (Part 2, step 8) and sign in.
  2. Open the Edge automation window and check LinkedIn is signed in (Part 2, step 7).
  3. Have one finished role ready — searched, and with 8–10 profiles already read. This is the one you show the ranked list on.
  4. Have a second, fresh job description in a text file, ready to paste. This is the one you run live.
  5. Check /admin/health is green and note how many reads are left today. If it says 0, the live read in section D will refuse — reschedule, or demo without it.

The walk-through

  1. What problem does this solve1 min · no screen

    “A job description goes in, and a ranked shortlist comes out — where every line about a person has a link to where we read it. It does not guess. If it cannot show you the source, it does not make the claim.”

  2. Paste a job description2 min

    New role → paste the job description → Read it. Point at the form it fills in: job titles, must-have skills, locations, years.

    “It read the description and filled this in. It is a draft — I get the final say, and nothing searches until I confirm. Notice locations are checkboxes: it will not go looking in a city I did not tick.”

    Tick a city if none is set, then Find candidates.

  3. The search runs2 min

    The page fills in on its own. While it does:

    “It is searching LinkedIn the way you or I would from Google — public search results only, no account involved at this step. Each result gets a first pass: right city, right kind of role. The ones that fail that pass are listed too, with the reason, so you can see when I have been too strict.”

    Scroll to “N we did not open” and read one reason out loud.

  4. Reading profiles2 min

    Scroll to Read LinkedIn profiles. Point at the budget line.

    “This is the rationed part. Thirty profile reads per 12 hours, shared across every role — ten spent here are ten unavailable tomorrow morning. It is deliberately slow, about 25 seconds a person, because that is what keeps my LinkedIn account healthy.”

    Set the number to 2, press Read them now.

    “It is reading through that Edge window over there — a real signed-in browser, one profile at a time. It tells me which person it is on. If LinkedIn ever shows it a wall, it stops, switches itself off, and says so on this page. It will never quietly return nothing and look successful.”

    Leave it running and move to the finished role for the payoff.

  5. The ranked list3 min

    Open the role you prepared. This is the part that matters.

    “Three groups, and the difference between them is the whole point.”

    • Ranked — checked, and matched.
    • Ruled out — checked, did not match, each with a reason.
    • Not looked at yet — nobody has read them.

    “That third group used to say ‘no sign of Python’ for people nobody had read — a claim about someone we never opened. It does not do that any more.”

    Click a person to open their card.

    “Every line has a source link and the exact words we read. And look at the labels — ‘Says so’ is what someone wrote about themselves. ‘Proven’ is something we could verify in their public work. Those two never get added together, all the way to this screen.”

    “The ranking is arithmetic — five things, fixed weights, the same answer every time. The sentence explaining it is written by an AI, but the AI never touches the number.”

  6. Close1 min

    “It will not collect age, gender, caste, religion, marital status or photographs. Not ‘collects but ignores’ — it does not read them at all. And it never stores anyone's email address in plain text. We identify people; you contact them the normal way.”

    Then go back to the live role from section D — the two profiles will have finished and folded into the ranking. That is the loop, start to end.

Not in a demo

Do not start a read with a big number to look impressive — it is minutes of watching a progress line. Do not re-read the same people to fill time; it spends the daily budget for nothing. And if it says Stopped, move to the prepared role and talk about that instead — never turn it back on to try again in front of an audience.

Part 2

Setting it up on your machine

Once. About half an hour, most of it downloads.

  1. Install these

    WhatWhereNote
    Docker Desktopdocker.comMust be running before the tool starts — look for the whale in the tray
    Python 3.13python.orgTick “Add to PATH” during install
    uvpip install uvInstalls the tool's dependencies
    Gitgit-scm.comTo get the code
    Microsoft EdgeAlready on WindowsThe automation window

  2. Get the code

    PowerShell
    git clone <repo-url> D:\hiring-intelligence
cd D:\hiring-intelligence
uv sync

  3. Start the database

    PowerShell
    docker compose up -d
python -m hi.db migrate

    migrate prints a list of applied files. If it hangs, Docker Desktop is not running yet.

  4. Make your login

    PowerShell
    python -m hi.auth hash 'pick-a-real-password'

    Copy the line it prints.

  5. Fill in .env

    Copy .env.example to .env and open it in Notepad — it explains every line. You need:

    KeyRequiredWhat it does
    HI_USERSYesYour email, a colon, then the hash from step 4
    SERPAPI_KEYYesThe search key — serpapi.com → API key. Without it, nothing is found
    ANTHROPIC_API_KEYOptionalReads job descriptions better. Without it, the form is still filled from keywords
    GITHUB_TOKENOptionalRaises a rate limit. Without it things are slower, not broken
    Easy to miss

    .env is read once at startup. Restart the app after you change anything in it, or you will be looking at the old value.

  6. Turn LinkedIn reading on

    PowerShell
    python -m hi.adapters.linkedin_profile enable

    It ships switched off. This is the one command that says “yes, use my real account”, and it records who ran it. Read what it prints.

  7. The LinkedIn window — the part people get wrong

    One line, in PowerShell, from the repository folder, each time you want to read profiles:

    PowerShell · one line · run from the repo folder
    & "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" --remote-debugging-port=9222 --user-data-dir="$PWD\var\edge-automation"
    • The leading & is required, and $PWD only resolves if you are in the repository folder — cd D:\hiring-intelligence first. A full path works just as well.
    • If that path errors, Edge is in the other standard location: drop the  (x86).
    • --user-data-dir is required too — Edge refuses remote debugging on your normal profile.
    • First time only: sign in to LinkedIn in that window. It stays signed in afterwards; the profile lives under var/, which never reaches the repository.
    • Leave it open and visible while reading. Do not minimise it to a hidden desktop.
    • The role page prints this same command with the right path for the machine it is running on — copy it from there if in doubt.
    Never

    This is a separate browser profile, not a separate account. Never sign a made-up, second or shared account into it. It is banned, it is the fact pattern that gets companies sued rather than blocked, and it returns less data — LinkedIn shows less history to low-standing accounts.

  8. Start the tool

    PowerShell
    uvicorn hi.web:app

    Open http://127.0.0.1:8000 and sign in with the email and password from steps 4–5. That one command is the whole application — the background work runs inside it. Leave that window open while you use the tool; closing it stops everything mid-search.

Part 3

Working, day to day

  1. Start Docker Desktop, or leave it running at login.
  2. docker compose up -d
  3. uvicorn hi.web:app
  4. Open the Edge automation window when you intend to read profiles.
  5. Work in the browser: New role → paste → confirm → wait → Read them now → shortlist.

The rhythm the budget forces

Thirty reads per rolling 12 hours. A role with forty people found cannot be fully read in one day, and that is the intended shape: read the top ten, look at the ranking, decide whether the role's must-have skills were right, and only then spend more. If the top ten are all wrong, editing the role beats reading thirty more people.

Two buttons worth knowing

  • Read them now — reads the next few profiles through the Edge window. Refuses in a sentence if the window is shut, the budget is spent, or a read is already running.
  • Find more people — searches one page deeper and re-checks everyone already found against the role as it stands. The re-check is free and instant; the deeper search costs searches and a few minutes.

Upkeep

  • Weekly — glance at /admin/health. Green means it has actually produced something recently, not merely that nothing crashed.
  • Monthly — check the SerpAPI quota before it runs out mid-search, and the “saved pages on disk” figure on the same page.

Part 4

When something looks wrong

RUNBOOK.md is written symptom-first for exactly this. These four are the ones you are most likely to meet.

What you seeWhat it meansWhat to do
Stopped: … on the reading panel LinkedIn showed a wall, and reading switched itself off Do not turn it back on today. Use LinkedIn normally for a while. If it happens twice, stop using the reading feature and say so — the tool works without it (RUNBOOK.md §8)
“The LinkedIn window is not open” The step 7 window is closed, or is on a different machine from the tool Open it, then press the button again
“All 30 profile reads are used up” Normal Nothing. It frees up gradually and the page names the time — it is a rolling window, not a midnight reset
“Searching…” forever The PowerShell window running the app was closed Restart uvicorn hi.web:app
Do this once

Back up, and then restore that backup into a scratch database — RUNBOOK.md §7 has the commands, including the version that runs inside Docker so you need no Postgres tools installed. An unrestored backup is a rumour.

Part 5

What it refuses to do, and why that is not a bug

  • No age, gender, caste, religion, marital status or photographs. Never collected, so they can never leak into a ranking.
  • No plain-text email addresses. Stored as a one-way hash only.
  • No second LinkedIn account, no proxies, no captcha solving. If a source needs those, we drop the source.
  • The caps live in the code, not in a settings file. Thirty a day, one at a time, twenty seconds apart, never a hidden window. Not adjustable by design — they are what keeps the account usable.
  • It will not merge “says they know Python” with “has eight years of public Python.” Different facts, kept visibly different all the way to the screen.

If someone asks for one of these to be changed, that is a conversation with a decision recorded in the architecture document — not a settings change.
